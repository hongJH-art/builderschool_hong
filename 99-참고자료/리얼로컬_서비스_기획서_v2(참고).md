## 00. 개정 이력 (v0.1 → v2)

2026-07-30 클라이언트 2차 미팅에서 백엔드 수정 사항과 큐레이터 운영 방식이 구체화되었다. v0.1 대비 주요 변경점은 다음과 같다.

| 구분 | v0.1 (1차) | v2 (2차 반영) |
|---|---|---|
| 큐레이터 맵 생성/편집 | ❌ 제외 (모의 데이터로 시딩) | ✅ **포함** — 큐레이터가 직접 맵 등록 가능 |
| 큐레이터 승인 | 클라이언트 수작업 (앱 밖) | ✅ **어드민 페이지**에서 관리자가 기존 회원 중 드롭다운으로 수동 지정 |
| 큐레이터 등급 | 단일 | **2등급** — 심사 면제 큐레이터 / 심사 필요 큐레이터 |
| 맵 등록 심사 | 미정 | 심사 필요 큐레이터만 관리자 심사 거침 (무분별한 맵 생성 방지) |
| 맵 정렬 기준 | 미정 | **저장(좋아요) 수 → 동률 시 후기 수** 순 |
| 이미지 등록 | 미정 | 맵 대표이미지: 큐레이터 직접 등록 / 장소 사진: 구글 API 자동 수집 |

## 01. 프로젝트 개요

리얼 로컬은 한국을 방문하는 외국인 관광객에게, 승인된 로컬 큐레이터가 직접 엄선한 맛집·술집·로컬 스팟을 지도 기반으로 소개하는 큐레이션 서비스다.

구글 맵처럼 검색 결과를 나열하는 대신, 신뢰할 수 있는 소수의 큐레이터가 만든 "지역 혹은 컨셉 단위의 맵"을 통해 이용자가 "누가 골랐는가"를 믿고 따라갈 수 있게 하는 것이 핵심이다. 큐레이터가 늘어날수록 맵이 쌓이고, 서비스 전체가 하나의 살아있는 가이드북이 되는 선순환 구조를 지향한다.

> **2차 미팅 명확화**: "맛집 앱"이라는 표현은 편의상의 표현이며, 정확히는 큐레이터 개인의 **취향을 보여주는 맵** 서비스에 가깝다. 맵 안에는 식당이 아닌 장소(카페, 술집, 로컬 스팟 등)도 포함될 수 있으나, 기능적으로는 모두 "음식점"으로 뭉뚱그려 취급한다.

## 02. 왜 이 서비스인가

클라이언트가 명시한 핵심 니즈는 "외국인이 왔을 때 믿고 들어갈 수 있는, 인증된 로컬의 찐 맛집 리스트"가 없다는 것이었다. 구글 맵은 정보는 충분하지만 필터링되지 않은 검색 결과일 뿐, 큐레이션이 신뢰의 근거가 되지는 못한다.

**차별점**

- **승인된 로컬이 만든다** — 누구나 리뷰를 남기는 구조가 아니라, 관리자가 어드민 페이지에서 승인한 큐레이터만 맵을 생성한다.
- **타겟이 뾰족하다** — 해외에서 한국으로 들어오는 관광객이라는 명확한 대상. 특정 출신 국가는 정하지 않고, 런칭 후 유입 데이터를 보며 조정한다. 지역(장소 소재지)도 서울·부산 등으로 제한하지 않고 전국 단위를 허용한다.
- **맵이 곧 가이드북이다** — 큐레이터가 늘어날수록 컬렉션이 쌓이는 구조로, 장기적으로 하나의 신뢰 기반 가이드북을 지향한다. 이번 라운드부터 큐레이터가 직접 맵을 등록할 수 있어 콘텐츠 확장 구조가 실제로 동작한다.

포지셔닝 카피: **"승인된 로컬이 만든 찐 맛집 가이드"**

## 03. 핵심 구조: 관리자 · 큐레이터 · 맵 · 장소

회의에서 가장 먼저 정리해야 했던 개념 구조다. **맵은 지역이 아니라 큐레이터 개인이 만드는 컬렉션**이다. "을지로"라는 지역 전체가 하나의 맵으로 자동으로 묶이는 것이 아니라, 한 큐레이터가 "을지로 로컬 맵", 다른 맵으로 "을지로 라멘 맵"처럼 원하는 만큼 여러 개의 맵을 만들 수 있다.

2차 미팅에서 **관리자(Admin)**가 명시적인 4번째 주체로 확정되었다. 관리자는 일반 회원 중 누구를 큐레이터로 지정할지, 그리고 심사 필요 큐레이터가 올린 맵을 승인할지를 결정한다.

```
Admin (관리자)              Curator (승인된 큐레이터)         Map (N개)                       Place (N개)
어드민 페이지에서       →   드롭다운으로 기존 회원 중     →  큐레이터가 직접 등록          →  맛집·술집·로컬 스팟
회원을 큐레이터로 지정      선택되어 권한 부여                예: 을지로 로컬 맵 / 라멘 맵      구글 맵 API로 지도 표시
                            등급: 심사 면제 / 심사 필요       대표 이미지는 큐레이터가 등록      대표 사진은 구글 API 자동 수집
                                                              심사 필요 큐레이터는                한 줄 소개 포함
                                                              관리자 승인 후 노출
```

> 맵 하나에는 큐레이터가 쓴 **한 줄 소개(설명)**가 있고, 이 설명은 맵 상세 화면뿐 아니라 맵 목록에서도 노출된다. 장소 개별 설명·순위 편집 기능은 이번 범위에서 제외했다 (05 MVP 범위 참조).

## 04. 사용자 및 기능 정의

사용자는 **관리자·큐레이터·일반 회원** 세 종류로 나뉜다. 결제·회원 등급 같은 기능은 없다.

### 관리자 (Admin) — 2차 미팅 신설

| 기능 | 내용 | 범위 |
|---|---|---|
| 큐레이터 지정 | 어드민 페이지에서 기존 가입 회원 목록을 드롭다운으로 조회해 큐레이터로 수동 지정. 별도 신청·승인 요청 절차 없음 | ✅ 포함 |
| 큐레이터 등급 설정 | 지정한 큐레이터를 "심사 면제" 또는 "심사 필요" 등급으로 구분 지정 | ✅ 포함 |
| 맵 심사 | 심사 필요 등급 큐레이터가 등록한 맵을 승인/반려. 심사 면제 큐레이터의 맵은 즉시 게시 | ✅ 포함 |

> 심사 면제 큐레이터는 클라이언트 지인 등 신뢰 기반 초기 인원, 심사 필요 큐레이터는 이후 신규 유입 인원을 상정한 구분이다. 관리자 화면 자체의 상세 UI(승인 대기 큐, 반려 사유 입력 등)는 06 화면 구성 및 10 확인 필요 사항 참조.

### 큐레이터 (Curator) — 2차 미팅에서 범위 확대

| 기능 | 내용 | 범위 |
|---|---|---|
| 지정 방식 | 스스로 신청 불가. 관리자가 기존 회원 중 선택해야만 권한 부여 | ✅ 포함 |
| 맵 등록 | 큐레이터가 직접 여러 장소를 하나의 주제로 묶어 맵을 생성 (기존 "모의 데이터 시딩" 방침에서 변경) | ✅ 포함 |
| 맵 대표 이미지 등록 | 맵 생성 시 큐레이터가 대표 이미지를 직접 업로드 | ✅ 포함 |
| 맵 다중 생성 | 한 명의 큐레이터가 컨셉·지역 기준으로 여러 개의 맵 보유 가능 | ✅ 포함 |
| 맵 등록 심사 | 심사 필요 등급 큐레이터는 맵 등록 시 관리자 승인 후 노출. 심사 면제 큐레이터는 즉시 게시 | ✅ 포함 |
| 장소별 설명·순위 편집 | 식당별 설명 작성이나 노출 순서를 큐레이터가 직접 조정하는 기능 | ❌ 제외 |
| 큐레이터 소개 페이지 | 큐레이터를 소개하는 프로필 페이지 | ❌ 제외 |

### 일반 회원 (General User)

| 기능 | 내용 | 범위 |
|---|---|---|
| 로그인 | 클라우드 DB 연동 계정. 로컬 저장이 아닌 서버 기반으로, 기기를 바꾸거나 분실해도 복구 가능 | ✅ 포함 |
| 큐레이터 신청 | 일반 회원이 스스로 큐레이터가 되겠다고 신청하는 절차 | ❌ 제외 (관리자 수동 지정만 가능) |
| 맵 탐색 | 전체 맵 목록 열람, 맵 상세 진입 시 지도 + 장소 리스트 확인. 정렬 기준: 저장 수 → 동률 시 후기 수 | ✅ 포함 |
| 현재 위치 표시 | 지도에 내 현재 위치 표시 | ✅ 포함 |
| 검색 | 맵/장소 검색 기능 | ❌ 제외 (불필요로 확정) |
| 맵 저장 | 마음에 든 맵을 "나의 리스트"에 저장 | ✅ 포함 |
| 장소 저장 | 맵 안의 개별 장소만 따로 모아 저장 (맵 저장 리스트와는 별도 목록) | ✅ 포함 |
| 공유 | 맵 전체 또는 장소 1건 단위로 링크를 통한 일반적인 외부 공유. 별도 공유 리스트 관리 기능은 불필요 | ✅ 포함 |
| 리뷰 작성 | 장소 단위가 아닌 **맵 전체 단위**로 후기 작성 — 실질적으로 큐레이터에 대한 평가 역할을 겸함 | ✅ 포함 |
| 결제/멤버십 | 결제 관련 기능 전체 불필요 | ❌ 제외 |
| 실시간 위치추적 가이드 | 큐레이터가 현장에서 도보 가이드하며 실시간 위치를 표시하는 기능 — 불필요. "현재 위치 표시"(내 위치를 지도에 보여주는 기능)와는 별개 항목이므로 혼동 주의 | ❌ 제외 |

## 05. MVP 범위 요약

"화요일까지 프론트엔드/와이어프레임, 목요일까지 백엔드 포함 전체"라는 일정을 고려해 범위를 잡았다. 2차 미팅으로 큐레이터의 맵 등록·관리자 어드민 기능이 범위에 새로 포함되어, 1차 대비 백엔드 작업량이 늘었다.

**포함 (Included)**
- 로그인 (관리자/큐레이터/일반회원 구분), 비로그인 열람 허용
- 어드민 페이지: 회원 → 큐레이터 지정(드롭다운), 등급(심사 면제/심사 필요) 설정, 맵 심사(승인/반려)
- 큐레이터 맵 등록: 장소 묶기, 대표 이미지 업로드, 한 줄 소개 작성
- 장소 대표 사진: 구글 Places API 자동 수집 (기술적 한계 시 임의 이미지 허용)
- 맵 목록 홈 화면, 정렬 기준(저장 수 → 후기 수) 적용
- 맵 상세 화면 (구글 맵 + 장소 리스트/리뷰 서브탭 + 한 줄 소개)
- 장소 상세 화면 (바텀시트), 영문명 + 한글명 병기
- 지도 내 현재 위치 표시
- **Map 탭 (신규)**: 전체 큐레이터의 게시된 맵에 속한 장소를 한국 전역 지도 하나에 통합 표시, 핀 탭 시 장소 상세로 진입
- 맵 저장 · 장소 저장 (저장 탭)
- 맵 · 장소 공유 (링크 방식)
- 맵 단위 리뷰 작성
- 지역/주소 자율 텍스트 입력 (전국 단위 허용, 시/구 고정 분류 없음)
- 영어 UI · 모바일 반응형
- 클라우드 DB 연동

**제외 (Excluded, 이번 라운드)**
- 큐레이터 자가 신청 (관리자 수동 지정만 가능)
- 장소별 설명·순위 편집
- 큐레이터 랭킹/비교, 큐레이터 소개 페이지
- 검색 기능
- 실시간 위치추적 가이드 (현재 위치 표시와는 별개)
- 길찾기 기능
- 결제/멤버십
- 네이티브 앱 (iOS/Android)
- 도메인 구매·연결 (클라이언트가 추후 진행)

## 06. 화면 구성 (정보구조)

1차 5개 화면(00~04)에 더해, 2차 미팅에서 확정된 **큐레이터 맵 등록 화면**과 **관리자 어드민 화면**이 추가된다. 여기에 이용자가 개별 맵 단위가 아니라 **전국 단위로 장소를 훑어볼 수 있는 Map 탭**을 하단 탭바에 추가로 배치한다. (00~04 상세 목업은 `docs/와이어프레임_화면설계.md`, 05~07 신규 화면은 `mockups/v2/와이어프레임_v2.html` 참조)

| 화면 | 구성 |
|---|---|
| **00 Login / Sign up** | 이메일 기반 로그인·회원가입. 비로그인 상태로도 Home·Map Detail·Place Detail 열람은 가능하며, **저장·리뷰 작성·공유 시도 시에만** 로그인 화면으로 유도 |
| **01 Home** | 맵 목록. 저장 수 → 후기 수 순으로 정렬된 맵 카드 나열. 각 카드에 맵의 한 줄 소개 노출 |
| **02 Map Detail** | 맵 상세. 상단: 구글 맵 API 연동 지도 + 현재 위치 표시, 장소 핀 표시 / 하단: `Places` · `Reviews` 서브탭 전환 |
| **03 Place Detail** | 장소 상세. Map Detail 위에 뜨는 바텀시트 형태. 영문명 + 한글명 병기. 장소 단위 저장·공유는 이 화면에서 처리 |
| **04 Saved** | 저장 탭. `Maps` · `Places` 서브탭으로 저장한 맵 리스트 / 저장한 장소 리스트를 구분해 표시 |
| **05 Map Create/Edit** *(신규)* | 큐레이터 전용. 장소 검색·추가, 대표 이미지 업로드, 한 줄 소개 작성. 심사 필요 큐레이터는 등록 후 "심사 중" 상태로 표시 |
| **06 Admin Console** *(신규)* | 관리자 전용. 회원 목록에서 큐레이터 지정(드롭다운) + 등급(심사 면제/심사 필요) 설정 탭, 맵 심사 대기 목록 + 승인/반려 탭 |
| **07 Map (전국 탐색)** *(신규)* | 하단 탭바 전용 화면. 게시된(published) **모든 큐레이터의 모든 맵에 속한 장소**를 하나의 한국 전역 지도 위에 핀으로 통합 표시. 특정 맵에 진입하지 않고도 지도로 장소를 훑어보는 용도. 핀 탭 시 03 Place Detail 바텀시트로 진입(02 Map Detail과 동일 동작), 현재 위치 표시도 동일하게 지원 |

> 하단 탭바는 `Home` · `Map` · `Saved` · `Account` **4개**로 고정한다 (v0.1·v2 초안 당시의 "3개 고정" 결정에서 변경됨 — 착수 전 클라이언트에게 이 변경을 명시적으로 확인 요망, 10절 참조). `Map`은 01 Home(큐레이터가 만든 맵 목록)과는 별개로, 장소를 지도 중심으로 탐색하는 보조 진입점이다. `Account`는 로그인 계정 정보용 진입점이며, 큐레이터 권한 보유 시 이 화면에서 "맵 등록" 진입점이 노출된다. 관리자 콘솔(06)은 하단 탭바와 분리된 별도 진입 경로로 둔다 (일반 이용자 플로우와 섞이지 않도록).

## 07. 디자인 방향

- **컬러** — 베이지에서 화이트로 이어지는 톤. 정확한 컬러 칩은 클라이언트가 보유한 레퍼런스 가이드북 자료 전달 후 확정 (현재 `design/디자인가이드.md` / `design/design-tokens.json`으로 정식화됨).
- **무드** — "핸드메이드 픽드(picked) 맵" 느낌. 딱딱한 플랫 UI나 AI가 만든 듯한 인상을 최대한 배제한다 — 2차 미팅에서 클라이언트가 명시적으로 재확인한 최우선 원칙.
- **명시적 지양 요소** — 클라이언트가 직접 언급한 "절대 안 되는 것": 누리끼리한(탁한 노란빛) 배경, 이탤릭 텍스트, 파란색 링크. 디자인 검토 시 체크리스트로 사용할 것.
- **레퍼런스** — 에어비앤비를 "예쁘다"는 인상으로 언급 (기능적으로 동일한 방향은 아님, 톤앤매너 참고용).
- **포지셔닝 카피** — "승인된 로컬이 만든 찐 맛집 가이드"를 톤앤매너 전반의 기준 문구로 사용.

## 08. 기술 요구사항

- **플랫폼** — 모바일 웹 기준 반응형. 네이티브 앱 아님 (추후 검토 가능).
- **지도** — Google Maps API 연동, 맵 안의 모든 장소를 지도 위 핀으로 표시. Geolocation으로 현재 위치 표시 지원.
- **장소 데이터 자동 수집** — 장소 등록 시 Google Places API로 대표 사진·기본 텍스트 정보를 자동으로 가져온다. API에서 실사를 가져오지 못하는 등 기술적 한계가 있는 경우 임의의 대체 이미지 사용을 허용한다.
- **맵 이미지 업로드** — 맵 대표 이미지는 Google API로 제공되지 않으므로, 큐레이터가 직접 업로드하는 이미지 업로드 기능이 필요하다 (저장소/파일 크기·포맷 제한은 10. 확인 필요 사항 참조).
- **주소/지역 입력** — 시/구 등 고정 계층 분류 체계 없이 자유 텍스트 입력. 지역 제한 없이 전국 단위 주소 허용.
- **장소명 다국어 표기** — 장소 상세 페이지에 영문명과 함께 한글명을 병기할 수 있는 필드 추가.
- **정렬 로직** — 맵 목록은 저장(좋아요) 수 내림차순 → 동률 시 리뷰 수 내림차순으로 정렬.
- **권한 체계** — 관리자 / 심사 면제 큐레이터 / 심사 필요 큐레이터 / 일반 회원 4단계 역할(role) 구분. 맵 게시 여부는 등록한 큐레이터의 등급에 따라 즉시 게시 또는 관리자 승인 후 게시로 분기.
- **데이터 저장** — 클라우드 기반 DB. 기기 로컬 저장은 지양 — 로그인만으로 어떤 기기에서도 저장한 맵/장소 리스트를 복구할 수 있어야 함.
- **언어** — UI 전체 영어 + 장소명 한글 병기.
- **배포/도메인** — 개발팀이 자체 배포. 도메인은 클라이언트가 추후 별도로 구매 및 연결.

## 09. 일정 및 예산

| 시점 | 내용 |
|---|---|
| **1차 리뷰 (화요일)** | 프론트엔드 / 와이어프레임. 디자인과 화면 흐름 위주로 클라이언트와 짧게 재확인 |
| **2차 납품 (목요일)** | 백엔드 포함 전체 구현. 로그인, 클라우드 DB, 구글 맵 연동, 어드민 콘솔, 큐레이터 맵 등록 기능까지 포함한 완성본 |
| **유지보수 (납품 후 2주)** | 버그 수정 범위로 한정. 신규 기능 추가는 별도 협의 필요 |

**예산**: 총 400만원 (유지보수 2주 포함). QA 별도 진행 없이, 개발 과업 기준으로 책정된 금액. 2차 미팅에서 큐레이터 맵 등록·어드민 콘솔이 범위에 추가되었으나 예산·일정 변경은 논의되지 않았다 — 목요일 납품까지 작업량 증가분을 소화 가능한지 팀 내부적으로 재점검 필요.

## 10. 확인이 필요한 사항

1차 문서의 미확정 항목 중 2차 미팅으로 해소된 것과, 새로 생긴 확인 필요 항목을 함께 정리한다.

### 2차 미팅으로 해소된 항목
- ~~타겟 국가~~ — 특정 국가 미지정, 런칭 후 데이터로 조정 (1차부터 확정 상태 유지)
- ~~큐레이터 승인 플로우~~ — 어드민 페이지 드롭다운 수동 지정 + 심사 면제/필요 2등급으로 확정
- ~~맵 정렬 기준~~ — 저장 수 → 후기 수 순으로 확정
- ~~지역 계층 구조~~ — 자율 텍스트 입력, 전국 단위 허용으로 확정
- ~~현 위치·검색 기능~~ — 현재 위치 표시는 포함, 검색은 불필요로 확정
- ~~공유 방식~~ — 일반 링크 공유로 충분, 별도 리스트 관리 불필요로 확정
- ~~맵 예시 데이터 출처~~ — 클라이언트가 기존 전달한 CSV 파일 사용으로 확정

### 여전히 확인이 필요한 항목
1. **정확한 컬러 팔레트** — 베이지~화이트 톤으로 방향만 확정. 클라이언트가 보유한 레퍼런스 가이드북 자료 수령 후 정확한 컬러 칩 확정 필요 (`design/디자인가이드.md` 진행 상태와 대조 확인).
2. **납품 일정의 실제 날짜** — "화요일", "목요일"로만 확정됨. 실제 캘린더 날짜를 클라이언트와 재확인 후 문서에 반영 필요.
3. **장소 상세 부가 정보(가격대 등)** — 와이어프레임 목업에 가격대(`$$`) 표기를 임시로 넣었으나, 회의에서 논의된 적 없는 항목. 실제 데이터에 가격대 정보가 있는지, 노출이 필요한지 확인 필요.
4. **맵 심사 UX 상세** — "심사 필요 큐레이터의 맵은 관리자 승인 후 노출"까지만 확정. 반려 시 사유 입력·재제출 흐름, 심사 대기 중 큐레이터에게 노출되는 상태 표시 방식은 미정 — 개발 착수 전 최소 스펙 합의 필요.
5. **맵 대표 이미지 업로드 스펙** — 파일 포맷/용량 제한, 저장소(스토리지) 방식 미정. 목요일 납품 일정 내 처리 가능한 최소 스펙으로 확정 필요.
6. **한글 식당명 병기 상세 사양** — "장소 상세 페이지에 영문명 + 한글명 병기"는 방향만 승인됨. 데이터 입력 주체(큐레이터 수기 입력 vs 자동 매칭), 표기 위치·포맷은 후속 확인 필요.
7. **범위 확대에 따른 일정/예산 재검토** — 큐레이터 맵 등록 기능과 어드민 콘솔이 이번 라운드에 새로 포함되었으나, 예산(400만원)·납품일 변경은 논의되지 않음. 목요일 납품까지 소화 가능한 작업량인지 내부 재점검 필요.
8. **하단 탭바 3개 → 4개 변경 재확인 (신규)** — 06절의 "하단 탭바 3개 고정"은 2차 미팅까지도 확정 사항이었으나, 팀 내부 요청으로 `Map` 탭(전국 지도 탐색)을 4번째 탭으로 추가했다. **클라이언트와 논의된 적 없는 변경**이므로 착수 전 확정 필요. 아울러 전국 지도에 모든 published 장소를 한 번에 렌더링할 때의 핀 개수 증가에 따른 지도 성능·클러스터링 필요 여부도 함께 확인 필요.
